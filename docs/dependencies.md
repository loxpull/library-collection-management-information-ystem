# 7. Внутренние зависимости

Внутренние зависимости серверных модулей определяют порядок взаимодействия при выполнении операций.

```text
FastAPI Host
    ↓
LoanModule
    ├── IReaderValidationService
    │       ↓
    │   ReaderModule
    │
    └── ICopyAvailabilityService
            ↓
        CopyModule

BookModule
    ↓
Contracts

CopyModule
    ↓
Contracts

ReportModule
    ↓
Сервисы получения данных каталога,
экземпляров и выдач
```

Взаимодействие между модулями рекомендуется выполнять через публичные сервисные контракты.

Например, перед выдачей книги `LoanModule` обращается к `ICopyAvailabilityService`, чтобы проверить доступность экземпляра.

```text
LoanModule
    ↓
ICopyAvailabilityService
    ↓
CopyModule
```

Для проверки читателя используется отдельный контракт:

```text
LoanModule
    ↓
IReaderValidationService
    ↓
ReaderModule
```

Такое разделение уменьшает связанность модулей и позволяет тестировать их независимо друг от друга.

# 8. Внешние зависимости

На этапе проектирования предполагается использование следующих компонентов.

| Зависимость | Назначение |
|---|---|
| .NET 9 | Платформа выполнения WPF-клиента |
| WPF | Создание пользовательского интерфейса |
| Python | Платформа выполнения серверного приложения |
| FastAPI | Разработка REST API |
| SQLAlchemy | ORM для доступа к данным |
| PostgreSQL | Хранение реляционных данных |
| Git | Контроль версий |
| OpenAPI / Swagger | Документирование и проверка API |

Конкретные версии библиотек должны быть зафиксированы в конфигурационных файлах проекта.

Перечисленные технологии являются предлагаемым стеком. Их фактическое использование необходимо подтвердить структурой и конфигурацией реализованного приложения.
