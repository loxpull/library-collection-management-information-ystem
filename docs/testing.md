# 15. Тестовая стратегия

Для информационной системы управления библиотечным фондом предусматриваются модульные и интеграционные тесты, а также проверка сборки приложения.

## 15.1. Модульные тесты бэкенда

Модульные тесты проверяют отдельные правила предметной области.

### Тест 1. Доступный экземпляр

**Условие:** экземпляр имеет статус `Available`, читатель активен.

**Ожидаемый результат:** проверка возможности выдачи завершается успешно.

### Тест 2. Экземпляр уже выдан

**Условие:** экземпляр связан с активной выдачей.

**Ожидаемый результат:** повторная выдача отклоняется с ошибкой `COPY_ALREADY_ISSUED` или эквивалентной ошибкой, предусмотренной реализацией.

### Тест 3. Заблокированный читатель

**Условие:** читатель имеет статус `Blocked`.

**Ожидаемый результат:** оформление новой выдачи отклоняется с ошибкой `READER_BLOCKED` или эквивалентной ошибкой.

### Тест 4. Возврат книги

**Условие:** существует активная выдача и выполняется возврат экземпляра.

**Ожидаемый результат:** фиксируется дата возврата, выдача становится завершенной, а экземпляр снова становится доступным при отсутствии других ограничений.

## 15.2. Интеграционные тесты

Интеграционные тесты проверяют совместную работу HTTP-маршрутов, бизнес-логики и базы данных.

### Сценарий 1. Успешная выдача

Ожидается:

- API возвращает успешный HTTP-статус;
- в базе создается запись о выдаче;
- экземпляр больше не доступен для повторной выдачи.

### Сценарий 2. Повторная выдача экземпляра

Ожидается:

- операция отклоняется;
- в базе не создается вторая активная выдача того же экземпляра;
- клиент получает сообщение об ошибке.

### Сценарий 3. Успешный возврат

Ожидается:

- сохраняется дата возврата;
- выдача отображается как завершенная;
- доступность экземпляра обновляется.

### Сценарий 4. Поиск книги

Ожидается, что поиск по названию, автору или ISBN возвращает соответствующие записи каталога.

## 15.3. Проверка сборки

После внесения изменений необходимо проверить:

- запуск серверного API;
- доступность базы данных;
- сборку WPF-клиента;
- корректность основных пользовательских сценариев.
